## 2. 难点一：局部动作正常，但热量没有离开系统

### 表象

泵请求提高、实际流量增加、冷板换热增加，但电池峰值温度改善很小。

### 根因空间

1. 热源算错；
2. 控制模式没进入；
3. PID/执行器没跟随；
4. 泵规格或阀阻力限制流量；
5. 冷板有热流但散热器温差不足；
6. 需要 chiller，但压缩机被座舱占用；
7. 冷量或功耗重复计算；
8. 指标峰值由初始状态决定。

### 当前实现的解决机制

- **IntegratedSimulator.run** 记录热源、冷板热流、散热器/chiller 热流、冷却液状态和电/热残差。
- **SeriesHydraulicNetwork.solve** 证明请求是否形成实际流量。
- 座舱与电池 chiller 共用统一压缩机能力。
- **simulation_metrics** 同时评价温度与附件能耗。

### 连续追问

1. 为什么加泵不一定降温？泵只提高搬运和局部换热，最终热汇可能受限。
2. 如何证明不是泵问题？看工作点、压降预算、流量和冷板热流。
3. 热去了冷却液后为什么还不够？冷却液是中间储能/传热介质，不是最终热汇。
4. 高温环境下散热器为什么弱？冷却液与环境温差减小。
5. 何时用 chiller？被动热汇不足且温度风险存在时。
6. 为什么要共享压缩机约束？座舱和电池不能各用一套不存在的满能力。
7. 怎么验证没有重复？总冷量限幅、压缩机功率唯一记账、热/电残差闭合。
8. 为什么结果仍只有 0.312 ℃？平均包含零收益工况，且部分峰值受初始状态/硬件能力主导。
9. 下一步如何确认？供应商 map、热管理台架和实车热流/温度数据。

## 3. 难点二：预测指标可能被时序泄漏高估

### 表象

滑动窗口训练损失下降，但泛化看起来异常好，或模型只学到均值。

### 风险

300 s 历史和 300 s 未来窗口相邻时高度重叠。若先生成窗口再随机切分，同一 episode 的近重复轨迹会进入训练和测试。

### 当前解决机制

- **SequenceDatasetBuilder._episode_split** 先划 episode。
- **_windows** 只在集合内部生成窗口。
- scaler 只拟合训练 episode。
- 分目标报告 MAE/RMSE/R²，避免座舱高 R² 掩盖电池/电驱。
- 残差预测把 persistence 设为基线。
- 预测只做有限阈值调度，健康异常确定性回退。

### 连续追问

1. 为什么随机窗口有泄漏？相邻窗口共享绝大部分样本。
2. 先按时间切就够吗？单条 episode 时间切仍可能分布高度相似，项目按 episode 隔离。
3. scaler 为什么也会泄漏？全数据统计量把验证/测试分布信息带入训练。
4. 历史热负荷是不是标签泄漏？不是，只使用当前和过去可得值。
5. 为什么用残差？降低绝对水平学习难度，强化变化量。
6. R² 0.476 还能用吗？只能作为有限趋势预警，需控制收益和回退共同证明。
7. 如何验证回退？invalid_forecast 与 baseline 轨迹完全一致。
8. 还剩什么风险？所有 episode 仍来自同一仿真器，真实域外泛化未知。

## 4. 难点三：控制命令与实际流量之间缺少物理闭环

### 表象

把泵占空比线性映射成流量可以让仿真运行，但无法解释不同管路、阀位、温度和架构下的能力差异。

### 当前解决机制

1. 管路用 Darcy-Weisbach。
2. 冷板同时计算压降和换热。
3. 泵曲线随速度缩放。
4. 网络累加命名部件压降。
5. Brent 求泵—系统交点。
6. 显式返回 stopped、blocked、no_intersection、solver_failure、ok。
7. 规格扫描用设计流量包络判不可行。

### 连续追问

1. 为什么不固定流量？会掩盖硬件能力和阻力变化。
2. 交点物理意义？泵压升恰好抵消系统压降。
3. 为什么用 Brent？一维有界根，鲁棒且不需要导数。
4. 为什么先检查 bracket？没有符号变化就不存在当前区间工作点。
5. 无交点为何不裁剪？裁剪会伪造可行性。
6. 如何定位压降？输出每个命名部件 pressure budget。
7. 为什么不用 CFD？大量动态和规格扫描需要系统级计算效率。
8. 如何升级？用泵台架、冷板压降/换热和散热器风洞 map 替换默认值。

## 5. 难点四：拟合好不等于参数可辨识

### 表象

多个热参数组合可能产生相似温度轨迹，仅报告低残差可能得到错误参数。

### 当前解决机制

- 多 episode 激励；
- 参数上下界和单位注册；
- 测量标准差归一残差；
- 参数归一化；
- Jacobian rank 与 condition；
- 边界命中与近似 CI；
- 独立 holdout；
- 局部/全局敏感性；
- maturity statement。

### 连续追问

1. 为什么低 RMSE 不够？参数相关性可能让不同组合等效。
2. rank=3 说明什么？当前三个参数在最优点附近的残差方向线性独立。
3. condition=6.44 说明什么？当前局部问题不严重病态，但不是全局保证。
4. holdout 为何重要？避免只验证拟合数据。
5. 为什么仍不是确认？holdout 与训练由同一正确模型生成。
6. 结构误差怎么办？真实数据、多工况、残差结构分析和替代模型比较。
7. 置信区间可信吗？只是局部线性近似，不包含模型结构不确定性。

## 6. 难点五：预热越激进，充电越快但综合未必更好

### 表象

cold rule 把充电从 37.58 min 降到 17.58 min，看起来“明显更优”。

### 隐藏代价

- 3.61 kWh 路线预调温能量；
- 到站 SOC 从 0.202 降到 0.148；
- 相对老化从 \(9.23e-5\) 增到 \(2.89e-4\)；
- 充电峰温更高。

### 当前解决机制

- 路线和充电串联，而非只模拟充电；
- 到站 SOC 储备；
- 站端、温度、SOC 和 IV 四重功率限制；
- 三目标 Pareto；
- 原始空间先求非支配；
- 推荐点做扰动验证。

### 连续追问

1. 为什么提前加热能快充？温度因子提高接受功率。
2. 为什么到站 SOC 下降？加热附件从电池取能。
3. 为什么激进规则老化更大？高温、SOC、倍率与 Ah 吞吐共同进入相对模型。
4. 为什么不用单一加权和直接搜索？可能漏掉非凸前沿且权重会隐藏权衡。
5. 为什么推荐 22.75 min？它在前沿内按展示权重折中。
6. 权重是谁定的？当前代码展示假设，不是用户偏好证据。
7. 站端降额会怎样？推荐策略仍可行，但充电增至 47 min。
8. 老化能否换算寿命？不能，未做电芯标定。

## 7. 难点六：快速试跑可能污染正式证据

### 风险

quick 运行如果覆盖稳定目录，报告可能混用快速模型、旧图和正式 CSV；程序仍能运行，错误却不容易被发现。

### 当前解决机制

- run id 独立目录；
- quick/formal 独立 latest pointer；
- plant/config SHA；
- formal 只有验证通过才 promotion；
- expected files 哈希；
- suite manifest 与 upgrade manifest；
- 文档摘要反查机器结果。

### 连续追问

1. 为什么 git commit 不够？结果文件可能由不同配置/随机种子/未提交状态生成。
2. plant hash 包含什么？src、experiments、configs。
3. 为什么还要 artifact hash？证明每个输出文件未被替换。
4. 为什么语义校验？哈希只能证明没变，不能证明内容正确。
5. quick 能做什么？烟雾测试；不能支持正式结论。
6. 如何防止旧结果？独立运行目录和正式 promotion。
7. 当前证据？23+44 哈希、verify 通过。
