# 11 局限性与改进方向

## 1. 总结

当前平台的强项是系统闭环、因果可解释、多工况比较和工件可追溯；最大短板是真实数据与量产约束缺失。改进不应先堆更复杂 AI，而应先提升物理参数、数据成熟度、验证独立性和功能安全基线。

## 2. 数据局限

### 2.1 全部核心数据为合成

影响：

- LSTM 可能学习仿真器偏差；
- 合成 holdout 不能检验结构误差；
- 工况分布不代表真实用户。

改进：

1. 接入部件台架与实车 CAN；
2. 按车辆、季节、路线隔离训练/验证/确认；
3. 保存数据版本、信号字典、同步与缺失规则；
4. 使用完全独立的车型或季节数据做 model confirmation。

### 2.2 场景覆盖有限

六个驾驶工况和三个充电情景不足以覆盖气候、老化、载荷、海拔、拥堵、泊车浸车、故障等。

改进：建立组合场景矩阵和基于风险的覆盖度，不只增加随机 episode。

## 3. 物理模型局限

### 3.1 电池

缺失：

- OCV/内阻真实二维或三维 map；
- 温度/SOC/老化容量变化；
- 模组空间温差；
- 热失控与传播；
- 电芯快充安全边界。

改进：HPPC、热响应、快充 map、冷板台架和多点温度；必要时升级多节点或电化学热模型。

### 3.2 电驱

解析效率面和固定损耗分配不是供应商数据。改进为转速—扭矩—电压—温度 map，并分别标定电机/逆变器热网络。

### 3.3 座舱

未建湿度、潜热、除霜除雾、人体舒适、分区送风。改进为湿空气模型、玻璃结露与多区热容，并用环境舱数据确认。

### 3.4 热泵

准稳态 Carnot 修正不含两相状态、动态结霜/化霜和压缩机包络。改进为供应商 map 或经过台架确认的降阶制冷回路模型。

### 3.5 液路

一维串联网络无法表达支路流量分配、气阻、局部三维不均和阀/泵真实 map。改进为图网络支路求解，并用台架压降和换热数据回填。

## 4. 数值局限

- 5 s 显式 Euler 未提供系统步长收敛报告。
- 解析分段函数在阈值附近可能产生导数不连续。
- 长时间累计账本虽闭合，但数值闭合不等于模型结构正确。

改进：

1. 1/2/5/10 s 步长收敛；
2. 对快动态模块使用自适应或半隐式积分；
3. 报告离散误差与参数不确定性，不只报残差。

## 5. LSTM 局限

- 电池、电驱 R² 只有 0.476/0.546。
- 所有训练和测试来自仿真域。
- 没有与 persistence、线性模型、TCN/Transformer 的完整消融。
- 没有 OOD 检测、置信区间或在线漂移监控。
- 300 s 窗口没有消融证明最优。

改进优先级：

1. 建立 persistence 和物理预测基线；
2. 分工况、分时域、峰值召回率评价；
3. 接入真实数据并做域差异分析；
4. 使用 ensemble/quantile/概率预测输出置信度；
5. 低置信时保持 deterministic fallback；
6. 最后再比较模型架构。

## 6. 控制局限

- 状态机阈值和 PID 参数是研究标定。
- 没有正式需求追溯、故障码、仲裁矩阵。
- 没有泵/阀/传感器卡滞、通信超时等完整故障注入。
- 没有实时性、算力、定点化验证。

改进：先形成量产式功能需求和安全概念，再做 MIL/SIL/HIL；AI 层始终不能绕过安全规则。

## 7. 参数辨识局限

- 合成数据由正确模型生成；
- 只辨识三个参数；
- 近似 CI 不含结构误差；
- 真实传感器偏差、时间对齐、相关噪声未建；
- 全局敏感性样本规模和分布来自当前实现。

改进：

1. 用台架/实车独立数据；
2. 同时估计初始状态与传感器偏差；
3. 设计可辨识激励；
4. 用 profile likelihood 或贝叶斯方法评估非线性不确定性；
5. 保留独立 model confirmation 集；
6. 做跨工况残差诊断。

## 8. 架构比较局限

- 仅 3 种简化拓扑；
- 仅 4 项排名指标；
- 场景等权；
- rank 丢失幅度；
- 无成本、质量、空间、NVH、可靠性、维修和供应链。

改进：建立多属性决策模型，权重来自需求方；增加故障场景与部件成本；用真实布局和压降/UA map。

## 9. 快充与老化局限

- 接受功率是分段规则，不是 BMS 真实 charging map。
- 最大电流、站效率和热管理功率是工程假设。
- 相对老化未做电芯标定。
- 未建锂析出、SOC 估计误差、充电器协议和站端动态。

改进：接入电芯多温度/SOC 快充 map、HPPC、循环老化和析锂约束；用站端日志验证功率账本。

## 10. 优化局限

- 网格只有当前 186 个候选；
- 推荐权重未由用户/产品需求确认；
- robustness 仅 6 个扰动；
- 未做概率约束、最坏情况或在线重规划。

改进：

1. 用更密或自适应采样验证前沿收敛；
2. 权重敏感性分析；
3. Monte Carlo 环境/到站/站功率扰动；
4. 鲁棒或机会约束优化；
5. 在线滚动更新，但保留 SOC 和温度硬边界。

## 11. 软件与验证局限

已有 61 tests 和强工件治理，但还不是量产软件验证：

- 无需求—代码—测试正式 traceability；
- 无覆盖率与 mutation testing 报告；
- 无静态分析和实时调度；
- 无 SIL/HIL；
- 无 ISO 26262/ASPICE 证据。

改进：需求编号、接口数据字典、故障注入、覆盖率、SIL/HIL、版本发布流程。

## 12. 分阶段路线图

### 近期：提高研究可信度

1. persistence/物理预测基线与消融；
2. 时间步收敛；
3. 参数与权重敏感性；
4. 更广场景和 Monte Carlo；
5. 代码覆盖率与结果自动审计。

### 中期：接入真实部件与台架

1. 电池、电驱、泵、冷板、散热器、热泵 map；
2. 台架参数辨识；
3. 独立 holdout 和 model confirmation；
4. 校准后重跑全部 formal suite。

### 长期：量产功能原型

1. 需求与接口；
2. BMS/VCU/HVAC/导航/充电协同；
3. 诊断、仲裁与安全降级；
4. MIL/SIL/HIL/台架/整车/季节测试；
5. 算力、成本、NVH、可靠性和供应链评估。

## 13. 修改后的证据契约

任何针对 **src/ev_thermal/**、**configs/** 或 **experiments/** 的改进都会改变 plant hash。不能在改代码后继续引用当前 formal 结果。必须：

1. 重跑 formal；
2. 重跑 calibration/architecture/charging/optimization 四套 suite；
3. 重建 upgrade manifest；
4. 运行 **experiments/verify_artifacts.py**；
5. 更新所有当前交付与面试文档数字。
